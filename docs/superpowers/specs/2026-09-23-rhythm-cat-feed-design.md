# 节奏猫咪独立推荐流场景设计

日期：2026-09-23。状态：用户已确认聊天中的玩法方案与开局、结算补全；本文待审阅，尚未开始产品实现。

## 1. 目标与已确认范围

在现有 Cocos Creator 3.8.5 工程新增独立场景 `RhythmCatFeedGameScene`。推荐流接入参照企鹅叠叠乐，猫咪、食物、背景、界面构图及动作按用户提供的视频还原，主页增加“节奏猫咪”入口。

参考来源：[那zara的抖音视频](https://www.douyin.com/video/7531786748461649210)。已取得的参考文件为 576×1136、30 FPS、32.666667 秒，含 AAC 音轨。分析副本位于 `/private/tmp/gem-rhythm-cat-reference/reference.mp4`，关键帧总览位于同目录 `contact-sheet.jpg`。临时文件可能被系统清理，制作开始时应保存所需参考及来源记录到项目的非发布目录。

用户已确认：

- 两只猫分别在左右半屏移动，支持双指同时拖动接食物。
- 还原奶油色背景、地板、冰淇淋、张嘴动作、碎屑特效、分数和爱心。
- 固定界面直接保存在场景中，可在 Cocos 编辑器里调整。
- 推荐流接入参照企鹅叠叠乐，并添加主页入口。
- 视频未展示的开局和结算补为：0 分、3 颗心开局，漏接扣心，片段结束结算，可重新开始。
- 首版音乐使用视频中的这段音轨。

这是参考片段的可交互还原。原视频从一局中途开始，显示的分数和剩余生命不作为新局初始值；完整歌曲、原始谱面、原图和完整游戏流程未提供。源素材级完全一致不是已验证的能力，制作验收以可见构图、角色轮廓、动作和下落节奏对照为准。

## 2. 画面与资源

### 构图

- 竖屏，奶油色墙面、浅棕色地板、中央细分隔线；角色位于地板上沿，保留参考中的底部留白。
- 黑猫在左、白猫在右；大眼睛、细描边，分别有闭嘴、张嘴和咀嚼的表现。接食物时有短促形变及棕色或粉色碎屑。
- 左上分数、右上三颗心、左上角返回入口；角色上方短暂显示“真棒！”“好耶！”等参考中的反馈文字。
- 食物以棕色与粉色冰棒、甜筒及连续堆叠的冰淇淋为主。左侧密集连续段、右侧较稀疏段和末段双侧交替均按视频时间记录，不用随机掉落代替谱面。
- 平台胶囊由抖音宿主提供。视频中的底部宝箱推广入口不属于已确认玩法，首版不增加宝箱系统；画面对应区域保留地板。

### 素材和编辑器所有权

采用参考帧对照的分层重建：背景、两只猫的身体和表情、各类食物、心形、碎屑、按钮均为独立资源。缺失或被遮挡部分通过图像编辑补绘；保持原视频风格，避免替换为企鹅叠叠乐的角色或大面积彩色面板。

资源存放于 `assets/res/rhythmCatFeed/`。发布目录只保留压缩后的素材、音轨和必要元数据，不包含参考视频或生成原稿。背景使用 JPG，透明角色和食物使用 PNG。小图按实际显示尺寸制作，复用 SpriteFrame 和预置对象池，报告文件体积和纹理解码内存。

设计坐标以宽 750、参考高度约 1479 为基础，保持人物和食物等比缩放。适配短屏及长屏时，顶部界面跟随安全区，玩法区域完整可见，多余高度由墙面、地板覆盖。不得把背景比例变化传递为角色拉伸。

背景、猫咪及动作部件、移动边界、嘴部判定点、食物与碎屑池、分数、心形、提示和结算按钮全部预置到 scene。控制器读取绑定和初始姿态，只改变必要的状态、位置和动画；不在运行时重建固定界面或覆盖编辑器配置的文案、尺寸、图片及基础布局。

## 3. 输入、谱面与一局规则

### 开局与双指控制

场景进入后显示两只猫及首批食物的准备画面，不增加开始弹窗。首次有效触摸开始本局并同步启动音乐和谱面。

触摸按开始位置分配给左猫或右猫，记录 touch ID；同一只猫同一时刻只接受一个手指。左右手指可以同时移动，抬起一侧不释放另一侧。拖动使用相对位移，手指穿过中线时仍控制原猫，猫的位置限制在自己的半屏边界内。鼠标用于桌面单侧预览；另提供仅供测试使用的双触摸验证方式。

按钮点击不触发开局或移动猫咪。节点、全局输入及抖音原生触摸恢复通道必须去重，不能让同一次触摸触发两次操作。进入后台、退出推荐流、结算和离开场景时释放手指绑定。

### 固定谱面与判定

从参考视频逐段记录食物的侧别、横向位置、类型和到达嘴部的时刻，形成独立可编辑的固定谱面。每个计分单元有唯一 ID、侧别、位置、命中时刻及外观类型；连续长串拆成连续单元，并用组合外观保持视频中的长条形状。

食物纵向位置由当前曲目时间与命中时刻计算。只有对应侧猫咪的嘴部与食物实际相遇才命中，不因按住屏幕自动吸附食物。采用连续时间区间或扫掠判定，避免低帧率跨过嘴部而漏判。

- 命中一个计分单元加 1 分，并播放对应猫的张嘴/咀嚼、碎屑和短文字反馈。
- 一个单元只可命中或漏接一次；同一单元不能既得分又扣心。
- 食物经过可接取区域仍未命中，扣 1 颗心。连续长串仍按单元判定，剩余生命不能变为负数。
- 生命为 0 时立即结束失败；曲目片段结束且尚有生命时结束成功。最后一帧先处理到期判定，再决定结算，只显示一次结果。
- 不添加强制吸附、自动接取、连击倍率、额外歌曲、关卡解锁或道具规则。

### 结算与重开

结算使用与本场景颜色、线条一致的简洁面板，显示成功或失败、本局分数，并提供“重新开始”和“返回主页”。不照搬企鹅场景中加生命、减速、广告复活等未确认功能。

重新开始回到 0 分、3 颗心，音频和谱面从头开始，清理食物、碎屑、文字、手指和动画残留。返回主页进入 `GameSceneName.Main`，恢复主页音频。

## 4. 音频与时间同步

从参考视频提取 32.666667 秒音轨作为本局曲目，不循环。录屏音轨已混入原局猫叫或命中声，这些声音会保留在固定音轨中，不能声称它们由本局玩家操作实时生成。首版不再叠加一套重复的猫叫命中声；玩家操作差异由画面和得分反馈表现。

本场景使用独立、预置的曲目 AudioSource，进入玩法时暂停项目通用背景音乐。音量和静音遵守现有设置。音轨、谱面和判定共享一条游戏时间轴；优先以可用的音频播放进度校准，静音或平台暂不提供可靠音频进度时使用可暂停的单调游戏时钟。静音不影响游玩。

正式开始前确保资源加载完成。首次手势解锁播放；音频启动失败时保持准备状态并允许再次点击，不让食物先运行几秒。缺少曲目、谱面或核心节点时明确提示加载失败，不上报场景已可玩。

推荐流退出、应用进入后台或全屏广告覆盖时同时暂停音乐和谱面，并记录进度；恢复时从同一进度继续，不累计后台时长，不重新播放曲目而保留旧食物。重开统一归零。不得直接沿用企鹅控制器中恢复时重播背景音乐的做法来驱动音游。

## 5. 推荐流、主页与共享改动

- 复用 `FeedAcquisitionService`：关键资源和可见节点稳定渲染后上报就绪；正式进入或首次真实触摸恢复后才允许开局。
- 推荐流预览显示准备画面，不推进谱面、不产生得失分、不扣心。与谱面绑定的曲目等待正式开局，防止预览阶段消耗歌曲。
- 离开推荐流停止当前场景的输入、曲目和广告请求。返回前台按有效局状态恢复；销毁时清理监听、计时器和异步回调。
- 注册 `GameSceneName.RhythmCatFeedGame`、场景 UUID 和 `gamescene` bundle 构建信息。
- 新增 `FEED_RHYTHM_CAT_CONTENT_ID`，未取得实际 ID 时设为空字符串，只有配置非空且精确匹配才路由到新场景。不复用企鹅的 ID，不改变未知 ID 的既有兜底。真实 ID 是正式推荐流直达验收的外部条件，不阻碍本地制作。
- 在现有 `NewMainScene` 列表增加“节奏猫咪”卡片，同步维护主页生成工具，只做局部新增。
- 广告沿用共享 `ADController` 的调度、冷却和有效性检查；新增场景归因名称“节奏猫咪”。不额外创建广告计时循环。全屏广告暂停/恢复时必须保证音画同步。

当前工作区正在新增口算玩法并移除部分旧游戏。实施时重新读取共享文件后做小范围合并，保留这些改动和已经调整的主页顺序，不恢复已删除资源，不整体重生成并覆盖其他场景。

## 6. 模块边界与错误处理

- `rhythmCatChart.ts`：参考片段的固定谱面、时长和视觉类型，独立于 Cocos。
- `rhythmCatRules.ts`：计分、生命、一次性判定和局内状态；纯逻辑，便于验证低帧率及边界事件。
- `rhythmCatFeedGameScene.ts`：读取场景绑定，协调双指输入、音频时间、表现、推荐流及结算。若音频/触摸适配明显膨胀，拆成专用小模块，不复制整份企鹅控制器。
- `RhythmCatFeedGameScene.scene`：固定节点、对象池、AudioSource、SpriteFrame、布局和可调参数。
- 离线资源与场景生成工具：生成并验证新增资源的 UUID、引用及导入元数据，不在运行时搭建固定界面。

异步音频、广告及场景加载回调须校验本局编号和场景存活状态，防止重开或离开后操作旧局。导航失败恢复按钮可用状态，允许重试。缺失必要绑定时给出具体节点名，不以空白场景冒充就绪。

## 7. 验收要求

1. 双指分别控制左右猫，抬起、跨中线、快速反向拖动和重复输入均不串控；UI 点击不移动猫咪。
2. 正确接取才得分，漏接扣心，每个单元只结算一次；0 心失败、曲目结束成功、重开及离开流程可重复操作。
3. 30/60 FPS 和短帧卡顿下相同输入产生一致的命中结果；后台和广告恢复后音轨与食物时间不持续偏移。
4. 实际 Cocos 渲染对照参考关键帧，检查猫咪轮廓、闭嘴/张嘴切换、地板线位置、留白、食物密度、颜色和碎屑表现，不以运行截图替代操作验证。
5. 检查 750×1334、750×1479、750×1624 及更长屏幕；无黑边、裁切、拉伸和安全区遮挡，固定 UI 可在编辑器调整。
6. 验证主页入口、返回、场景及资源引用、推荐流预览就绪/进入/退出、音频暂停恢复和广告归因；相关现有玩法回归仍通过。
7. 执行必要规则与控制器测试、场景引用检查、TypeScript 检查和 Cocos 构建；平台测试使用模拟 API，不发送真实广告或测试埋点。
8. 抖音真机的双指、音频解锁、推荐流切入和广告返回须单独记录。未真机实测或未配置真实 Content ID 时，不将本地测试报告为正式上线完成。
