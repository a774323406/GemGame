# 外卖精准投送推荐流：设计说明

日期：2026-09-21。状态：对话方案已确认，本文待用户审阅；尚未开始实现。

## 1. 目标和已确认范围

在现有 Cocos Creator 3.8.5 项目中新增独立的“外卖精准投送”小游戏，尽量还原参考视频的画面比例、人物动作、投掷节奏和结算布局。支持抖音推荐流直玩，也可从正式主页 `NewMainScene` 进入。

参考视频：用户提供的 `2fd50b20b68c20d7ca4ec787e2c14d76.mp4`，分辨率 592×1280，时长约 34.13 秒。

用户已确认：

- 背景图片为 **750×1624 的 JPG**。
- 不复刻幸运宝箱；也不制作视频中的平台引导弹窗、系统胶囊或手机系统界面。
- 手臂自动快速旋转，点击按当时方向投出食物。
- 五份食物全部送对才通关；误投掉落、砸到保安则失败。
- 保留返回主页、重新开始；“下一关”进入相同玩法的新一轮，不扩展额外地图。
- 固定界面放进 scene，位置、尺寸、文字和图标可在编辑器中调整。
- 接入现有推荐流、插屏广告和广告事件归因。

视频展示了成功送达和失败，但没有展示五单完成后的完整成功流程。上述五单通关和下一轮规则是已经过用户确认的补足，不是声称从视频中观测到的行为。

不新增体力、道具商城、排行榜、宝箱、付费功能、服务器或广告复活限制。既有玩法不改规则，不恢复已经下线的奶茶、笔芯和旧主页。

## 2. 画面和素材方案

采用“参考帧拆图 + 缺失部分补绘”的分层方案。相较全部重新生成，更容易保留视频中的人物姿态、轮廓和颜色；遮挡、压缩噪点、无法拆开的手臂等部分需要重绘，不能承诺源素材级像素完全一致。

### 构图

- 上方蓝天、白云；左上蓝圈黄箭头返回按钮，白字黑描边标题，下方五颗星。
- 左下黄色头盔骑手、黄色电动车和送餐箱；转动的手臂独立于身体。
- 右侧浅色楼房、五个订单气泡；从上到下为绿色饮料、冰淇淋、蛋糕、汉堡、可乐。
- 右下保安和禁令牌；底部道路及地下土层，保留视频的大块下方留白。
- 待投食物显示在骑手上方，手臂方向用小黑点指示；送对订单出现绿色勾选。

### 分层和资源约束

- `background.jpg`：仅包含蓝天、云、远景树木、道路和土层，不把交互物体或界面烘焙进去；文件必须为 750×1624。
- 楼房、骑手/电动车、手臂、保安/牌子、五种食物、订单气泡、星星、勾选和按钮使用独立透明素材；同一食物用于待投图标、飞行物和订单图标，共享 SpriteFrame。
- 固定主体优先使用骨骼无关的分层旋转/位移，避免大尺寸逐帧图片。小图按实际显示大小制作，禁用无用 mipmap，不新增运行时大尺寸 RenderTexture。
- JPG 减少磁盘包体，不等于减少同尺寸解码内存；750×1624 的 RGBA 纹理约 4.65 MiB，内存统计与压缩文件体积分别记录。
- 素材由图像生成/编辑工具辅助补绘，后处理只负责尺寸、透明清理、压缩和导入元数据；生成的原始大图不放进发布资源目录。

### 屏幕适配和编辑器所有权

- 场景设计画布使用 750×1624；背景等比覆盖屏幕，不拉伸人物和楼房。
- 标题/返回对齐顶部安全区，核心投送区域按同一比例缩放，短屏不能把最高订单或骑手裁掉；较长屏的多余区域由背景覆盖。
- 顶部系统胶囊区域留空，不复制系统按钮。
- 背景、楼房、骑手、手臂旋转支点、保安、订单、星星、飞行物节点、方向点和结算按钮均预置到 scene。
- 控制器只更新必要的动作、订单进度和显隐；不重新指定编辑器已配置的标题、按钮文字、字体、SpriteFrame、基础位置或尺寸。
- 动画以编辑器配置的初始姿态为基准；命中区由场景里的独立节点确定，避免更换图或调整位置后视觉与判定分离。

## 3. 一局玩法

### 开始与瞄准

主页进入后直接显示玩法并开始手臂转动，不加开始弹窗。每局有五种不同食物，订单位置固定。首次进入和下一轮打乱投送顺序，每种只出现一次；“重新开始”沿用当前一局的顺序。

手臂绕肩部连续转动一整圈，首版旋转周期为 0.75 秒（480°/秒），作为可在编辑器调整的参数。方向点与手臂共享同一个当前方向；不会自动瞄准目标，也不会在点击后偷偷修正角度。

### 投出与判定

1. 游戏区域第一次有效点击，锁定该时刻的手臂方向，从手部投出当前食物。
2. 食物按初速度与重力飞行，视觉旋转和轨迹保持连续；初速度、重力、旋转速度与目标碰撞范围为可编辑参数。所有五个订单都必须存在可命中的发射角度。
3. 一次只允许一份食物在飞行中。其间重复点击不生成第二份食物，不重复消费订单。
4. 只有食物种类与尚未完成的目标一致，且飞行轨迹实际穿过对应订单气泡的收件区，才算送达。命中范围不扩展到整个楼层高度。
5. 成功时食物缩入目标、目标亮勾、增加一颗星，再准备下一份。第五份送达后只触发一次成功结算。
6. 投中错误收件区或楼体时不记分，食物被挡落；砸到保安、落地、飞出游戏边界或飞行超过 4 秒后失败。保安采用可见身体范围判定，不将整条道路当作保安。
7. 成功/失败结算后禁用投掷，保留本局星星和勾选供玩家查看。

逻辑采用固定时间步或等效连续判定。高速食物检测上一位置到当前位置的扫掠路径，不能因低帧率越过目标或保安而漏判。

### 结算与重开

- 失败：全屏半透明遮罩、提示“差点就成功了，重新试试吧”和橙色按钮；保留“返回主页 / 重新开始 / 下一关”的竖排布局。
- 成功：沿用同一套布局与橙色按钮，显示“投送成功”及五颗亮星，不套用打瓶子的专属结算皮肤。这些文字只作为 scene 的初始配置。
- 返回主页统一进入 `GameSceneName.Main` 对应的 `NewMainScene`。
- 重新开始和下一关都清空本局飞行物、星星、订单完成状态、失败提示和残留动画；重新开始重放本局顺序，下一关重新打乱五份订单。
- 不新增免费次数限制或必须看广告才能重开的规则。
- 背景音乐默认沿用项目现有背景音乐；投出、送达和失败增加简短匹配音效，遵守项目音量/静音设置，推荐流预览不主动播放声音。

## 4. 推荐流、主页和广告

### 推荐流生命周期

- 预览卡片必须显示完整背景、人物和订单，手臂持续转动；不自动投掷、不扣订单、不产生胜负、不请求广告。
- 资源与关键节点完成稳定渲染后，通过现有 `FeedAcquisitionService` 上报场景就绪，避免尚未渲染就上报导致黑屏卡片。
- 正式 `feedEnter` 后允许投送。首次真实触摸可使用项目现有的进入状态恢复机制，避免漏掉宿主事件导致界面永久锁住；同一次输入不能重复投两次。
- 页面退出或进入后台后停止该场景的动作、输入与声音；恢复时继续有效的一局，不根据后台停留时长推进飞行或直接判负。
- 销毁时解绑节点/全局/原生输入和生命周期监听、清理回调；解绑过程容忍节点已经销毁。

### 路由和主页

- 新场景：`FoodDeliveryFeedGameScene`，纳入 `gamescene` bundle 与 `GameSceneBundle` 的场景注册/UUID 映射。
- 新推荐流常量：`FEED_FOOD_DELIVERY_CONTENT_ID`，未取得真实 ID 时明确设为空字符串，且路由匹配必须检查配置非空。不得虚构 ID、复用别的玩法 ID 或改变未知 ID 的既有兜底。
- 用户提供实际 ID 后只需填写该配置并验证路由；在此之前主页可以体验，不能声称正式推荐流已上线。
- 在 `NewMainScene` 现有列表末尾增加“外卖精准投送”卡片，沿用主页卡片样式、网格间距和滚动行为，卡片本体及缩略图保存到 scene。
- 同步维护主页离线生成工具，使后续生成不会丢失新入口；不整场覆盖用户在编辑器中的无关修改。

### 广告

- 使用已有全局 `ADController`，不为该玩法另外创建无限广告计时器，不添加触摸拦截层或强制暂停引擎。
- 当前共享策略为启动至少 31 秒、推荐流正式进入至少 2 秒后满足条件才请求；全屏广告结束后至少冷却 60 秒，失败沿用现有退避。
- 预览、退出、后台或失效场景不弹插屏；加载中的迟到回调不能在已离开的场景强行展示。
- 插屏成功展示事件 `interAdType` 的 `feedType` 为“外卖精准投送”。若后续已有通用入口触发激励，其 `adType` 同样按当前场景归因，不增加本版未约定的激励按钮。

## 5. 实现边界

模块分工：

- `foodDeliveryRules.ts`：不依赖 Cocos 的订单、飞行、碰撞结果和局内状态；同一个投掷最多结束一次，同一个订单最多计分一次。
- `foodDeliveryFeedGameScene.ts`：读场景绑定和调节参数，处理输入、表现、音频、结算与推荐流生命周期；不负责动态搭建固定界面。
- `FoodDeliveryFeedGameScene.scene`：持有固定节点、图标、文字、碰撞区和参数，编辑器中即可查看和调整。
- `assets/res/foodDeliveryFeed/`：压缩后的发布素材及导入元数据。
- 离线素材/场景工具和测试：用于可重复导入、引用校验与行为验证，不在游戏运行时执行。

共享改动限制在场景注册、推荐流配置和路由、广告归因以及新主页入口。保留当前工作区正在进行的旧玩法移除，不恢复旧文件，不改其他游戏难度和广告时序。

场景绑定或资源缺失应给出具体错误；未就绪时不提前上报推荐流可玩。主页跳转失败需解除导航锁并允许重试，不留下不可点击的大厅。

## 6. 验收标准

### 规则和状态

- 每局五种食物不重复；仅正确食物进入正确区域可得分，五单完成恰好一次通关。
- 错目标、保安、地面、越界和超时路径可结束失败，不会永久卡在飞行中。
- 连续点击、重复宿主事件、重复碰撞不能多发食物或重复得分。
- 重开、下一轮、返回主页、后台恢复均无上一局残留状态。
- 相同起始条件在 30/60 FPS 下落点和结果一致；大帧间隔不会穿过命中区。

### 场景和视觉

- 背景文件实测 750×1624，所有新增图片报告压缩体积、纹理尺寸和预计解码内存。
- 场景引用及资源 UUID 校验通过，所有新增固定按钮和结算界面在编辑器中可见、可调，不依赖运行时生成。
- 在 750×1624、750×1334 和更长屏幕比例检查：标题不被人物遮挡、五个订单完整、按钮不重叠、核心玩法不裁切、没有黑边或黑底露出。
- 使用实际 Cocos 渲染截图对照视频检查人物比例、楼层间距、颜色、手臂转动、投掷与失败反馈；截图不能替代实际输入验证。

### 接入和回归

- 主页卡片点击进入正确场景，返回仍是新主页；配置真实 ID 后直玩进入相同玩法。
- 预览先稳定显示且转动，正式进入后第一次有效触摸即可投掷，退出后无广告/输入残留。
- 广告归因正确、共享冷却有效，插屏不额外锁输入；测试只模拟平台 API，不向真实广告或埋点服务发送测试事件。
- 新增规则测试、场景校验、主页/推荐流相关回归、TypeScript 检查和 Cocos web-mobile 构建通过。
- 抖音真机需要单独验证：触摸、推荐流预览切入、后台恢复、插屏关闭恢复。未实测时明确记录，不将本地模拟当作真机通过。
