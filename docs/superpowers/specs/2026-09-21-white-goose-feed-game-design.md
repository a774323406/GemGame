# 套大鹅玩法移植设计

## 背景

将 Creator 2.4.12 项目 `村口过庙会01_restore` 中的 `g_whitegoose`（套大鹅）玩法移植到当前 Creator 3.8.5 项目。目标项目已有“敲钉子”等同来源移植玩法，本次沿用相同的独立场景、可编辑 UI、主界面入口和推荐流生命周期结构。

第一版以完整可玩、保留原动画观感和便于后续在 Creator 编辑器中微调为目标。源项目的金币、任务、古董、宝箱、分享奖励及道具系统不迁移。

## 目标

- 新增可从 `NewMainScene` 进入的“套大鹅”玩法。
- 新增推荐流入口，内容 ID 暂时使用用户指定的字面值 `"xxx"`；获得正式 ID 后只替换配置常量。
- 保留原玩法的大鹅 Spine 动画、投圈手动画、三色套圈、场景美术、背景音乐和大鹅叫声。
- 将 Creator 2.4 逻辑重写为 Creator 3.8 TypeScript，不直接复用旧 prefab 或旧组件脚本。
- 固定 UI、节点位置和尺寸保存在 `.scene` 中，业务脚本只管理玩法和状态。
- 删除所有原项目奖励、货币、任务和商城依赖。

## 非目标

- 不迁移金币入场费用、古董奖励、幸运宝箱、分享奖励、任务进度或原项目存档。
- 不迁移原“简介/付费进入”页面，进入场景后直接开始游戏。
- 不为第一版重新绘制大鹅、手部或场景美术。
- 不修改现有“敲钉子”或其他玩法规则。

## 方案选择

采用“Creator 3.8 原生重建”方案：复制必要的原始图片、Spine 和音频，在 3.8 中新建独立场景，并用新的 TypeScript 控制器实现规则。

不采用直接转换 2.4 prefab 的方式，因为组件序列化格式、事件绑定和 Spine 引用跨大版本不可靠；也不采用普通图片简化动画的方式，因为会丢失原玩法的走动、躲避和套中表现。

## 场景结构与适配

场景采用 `750 × 1624` 设计尺寸和固定宽度适配。背景等比覆盖可视区域并裁切，不做非等比拉伸。顶部控件考虑安全区，交互按钮不贴近刘海或系统手势区域。

主要节点层级：

1. `Canvas`
2. `Background`
3. `GameField`
   - `GooseSlots`：10 个预设位置
   - 每个位置包含 `Shadow`、`GooseSkeleton` 和独立触摸区域
   - `ThrownRingLayer`：飞行中和落地套圈
   - `Foreground`：源场地前景，用于正确遮挡
4. `ThrowingHand`
5. `Hud`
   - 返回按钮
   - 套中进度 `0/7`
   - 剩余套圈 `10/10`
   - 看广告增加套圈按钮
6. `ResultOverlay`
   - 成功与失败共用遮罩和面板
   - 成功操作区
   - 失败操作区

大鹅容器根据纵向位置确定显示层级，使靠下的大鹅和套圈显示在靠上的对象之前。固定层级和布局都保存在场景中；代码只切换显示、状态和动画。

## 回合规则

### 初始状态

- 每局从 10 个预设位置中随机选择 7 个位置显示大鹅。
- 初始套圈数为 10。
- 套中目标为 7 只。
- 每次重开重新选择位置，并清空所有动画和进度。

### 大鹅状态

每只大鹅在以下状态间转换：

- `walking`：左右移动 3～5 秒，接近屏幕边缘时转向。
- `posing`：在原 Spine 的站立/闪避姿势中切换。
- `caught`：播放与当前套圈颜色对应的套中皮肤和动画，随后从场上移除。

保留源玩法判定：走动状态和 `s1` 姿势不能被套中；处于 `s2`、`s3` 或 `s4` 有效姿势时，成功率为 70%。未命中时播放对应躲避表现并终止当前连续命中。

### 投圈流程

- 点击大鹅触摸区域时，记录目标并播放手部 `reng` 动画。
- 点击空地时，记录触摸位置并按该位置投出套圈。
- 每次投掷立即消耗 1 个套圈。
- 投掷开始后锁定输入，直到飞行动画、大鹅反馈和状态更新全部完成。
- 套圈颜色从蓝、黄、红三种中随机选择；手部 Spine 皮肤和飞行套圈颜色保持一致。
- 命中时播放随机一段大鹅叫声。

### 结束条件

- 套中 7 只大鹅后成功。
- 套圈耗尽且仍有大鹅未套中时失败。
- 游戏中不计算或发放金币、物品或其他奖励。

## HUD 与结算

HUD 显示：

- `已套中 X/7`
- `套圈 N/10`；通过广告获得额外套圈后，分母同步变为当前可用上限，避免显示负数或超过上限的歧义。

顶部“增加套圈”按钮和失败弹窗的复活按钮都调用激励视频：

- 完整观看后增加 5 个套圈。
- 游戏中增加套圈时继续当前回合。
- 失败弹窗复活时保留已套中的大鹅和当前场面，并关闭弹窗继续游戏。
- 广告失败、取消或未完整观看时不增加套圈、不修改进度，并显示简短提示。
- 广告请求进行中禁用相关按钮，防止重复请求。

成功弹窗包含：

- “再玩一次”：重置并开始新回合。
- “进入拼豆”：完成推荐流会话并进入 `GameScene`。
- “返回”：完成推荐流会话并返回 `NewMainScene`。

失败弹窗包含：

- “加套圈”：观看广告增加 5 个套圈并继续。
- “重新开始”：不看广告，清空进度开始新回合。
- “返回”：结束当前体验并返回 `NewMainScene`。

所有结算页面不显示金币、古董、宝箱、奖励数量或分享奖励。

## 主界面入口

在 `NewMainScene` 两列滚动列表末尾新增一张与现有卡片尺寸和圆角一致的卡片：

- 标题固定为“套大鹅”。
- 预览图使用源项目已有“照片”素材或由该素材裁切得到的轻量图片。
- 点击卡片加载 `WhiteGooseFeedGameScene`。
- 跳转期间与其他玩法一致，锁定所有玩法按钮，加载失败时恢复并提示。

## 推荐流生命周期

- 推荐流内容 ID 常量暂时为用户指定的 `"xxx"`。
- 路由识别该 ID 后直接加载 `WhiteGooseFeedGameScene`。
- 推荐流卡片预览阶段允许场景稳定展示，但正式进入事件到达时必须重新开始完整回合。
- 正式进入前不接受游戏操作。
- 正式进入后按现有推荐流机制安排插屏。
- 应用进入后台、激励视频播放期间暂停背景音乐；回到前台后按当前状态恢复。
- 离开、成功进入拼豆或销毁场景时只完成一次推荐流会话，并取消未触发的插屏任务。
- 普通主界面入口不启用推荐流限制，但使用同一套玩法逻辑。

## 音频

- 场景玩法期间循环播放源“套大鹅背景音乐”。
- 命中大鹅时在三段原叫声中随机播放一段。
- 所有 UI 按钮复用项目现有 `buttonsound`。
- 音乐开关、音效开关、应用前后台和广告暂停均通过现有 `AudioManager` 管理，不直接调用平台音频接口。
- 返回主界面或进入拼豆时恢复目标场景应使用的背景音乐。

## 稳定性与错误处理

- `onLoad` 校验所有必需场景绑定；缺失时输出包含具体属性名的错误并停止玩法初始化。
- 投圈、Spine 完成监听和广告异步回调都携带回合序号；场景销毁或回合重置后到达的旧回调直接忽略。
- `onDestroy` 取消事件、计时器、Tween、Spine 完成监听和推荐流监听。
- 所有节点访问先检查有效性，避免场景切换时访问已销毁节点。
- Spine 动画名或皮肤缺失时记录警告并回退到可继续游戏的静态/基础动画，不让整局卡死。
- 推荐流 ID `"xxx"` 是有意保留的临时配置值，不在代码其他位置重复硬编码。

## 测试与验收

### 自动检查

- 规则测试：随机选 7/10、套圈扣减、成功、失败、广告增加 5 圈和重开重置。
- 资源测试：核心图片、Spine、音频和场景引用存在；不包含原奖励脚本或奖励 prefab 依赖。
- 场景测试：控制器必需属性均绑定，固定 UI 节点位于 `.scene`。
- 入口测试：主界面卡片跳转、场景枚举和 UUID 映射一致。
- 推荐流测试：`"xxx"` 能映射到套大鹅场景，正式进入时重置，离开时完成一次会话。
- 编译检查：TypeScript 和现有 Node 测试全部通过。

### 手动验收

- 从主界面进入可以完整游玩、重开和返回。
- 在 750×1334、750×1624 及更长屏幕上背景不拉伸，顶部按钮不被遮挡。
- 手机上点击大鹅和点击空地都能正确投圈，不出现一次触摸触发两次或无法触摸。
- 大鹅走动、躲避、套中、手部投圈、三色套圈和声音表现正常。
- 套圈耗尽显示失败；广告成功后保留进度继续；广告失败不增加套圈。
- 套中 7 只显示成功；进入拼豆、再玩一次和返回都可用。
- 普通入口与推荐流入口均不会出现空引用、销毁回调或重复结算错误。

## 第一版完成标准

满足上述自动检查和手动验收项，即认为第一版完成。动画速度、命中难度、节点尺寸和按钮位置作为后续微调内容，不阻塞第一版交付。
