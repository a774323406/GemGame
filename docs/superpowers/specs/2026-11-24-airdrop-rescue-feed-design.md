# 空投救援推荐流玩法设计

## 意图

新增一个与参考视频同类的推荐流玩法。玩家点击直升机携带的蔬菜，让蔬菜落入下方玻璃瓶，帮助瓶中的小猪获得食物。玩法重点是多架直升机从屏幕外进出、多个蔬菜同时下落，以及瓶口接取的即时判定。

## 已确认范围

- 目标场景名暂定为 `AirdropRescueFeedGameScene`。
- 开局倒计时 300 秒，显示食物 `0/5` 和机会 `25/25`。计时在推荐流场景稳定渲染后、玩家第一次触摸时开始，预览停留不消耗时间。
- 直升机从屏幕外左右进入，数量和出现间隔随机，可同时存在多架。
- 每架直升机携带一份蔬菜。点击直升机或其吊菜命中区域后释放这一份蔬菜，蔬菜按重力自由下落。
- 未点击的直升机和蔬菜飞出屏幕后直接回收，不扣机会。只有已经释放的蔬菜落空或越过场景底部才扣机会。
- 蔬菜落入瓶口判定区域时食物加一，落到瓶外或屏幕底部时机会减一。
- 接满 5 份食物成功，机会归零或倒计时结束失败。
- 底部保留视频中的“跳关、加时、提示”三个带广告标识按钮。
- 加入 `NewMainScene` 主界面。推荐流 ID 配置保留 `xx` 占位，但未知或占位值不参与正式路由，补入真实 Content_ID 后再开启推荐流入口。
- 资源预算允许超过 1 MB，以画面效果为优先。
- 结算复用项目现有推荐流全屏结算规范，不使用视频中的弹窗样式。
- 推荐流插屏、激励视频、返回按钮、背景音乐和结算按钮复用现有框架。插屏不主动暂停游戏。

## 目标

- 画面结构、运动节奏和操作反馈接近视频。
- 支持多目标并行运动和多颗蔬菜同时下落。
- 瓶口判定稳定，命中与落空都能在同一帧状态更新中正确扣分或加分。
- 运行时不依赖临时创建固定 UI，固定界面节点可在 Cocos Creator 中编辑。
- 短屏和长屏都能保持标题、状态、瓶子和底部按钮的安全边距。

## 非目标

- 不复刻视频里的弹窗式结算，不新增“喊人”按钮。
- 不修改拼豆 `GameScene` 或其他已停止维护的玩法。
- 本轮不执行 Cocos 构建，由用户自行构建测试。

## 实现方案

### 方案 A：完整复刻视频

为直升机、蔬菜、玻璃瓶和小猪制作独立素材，并为所有固定 UI 建立专用序列化场景。画面最接近视频，但素材和场景制作成本最高。

### 方案 B：轻量程序绘制

复用现有背景和按钮，主要角色用运行时节点与简单贴图组合。包体最小，但玻璃瓶、直升机和角色质感会明显偏离视频。

### 方案 C：混合方案（已选择）

复用现有推荐流背景、标题、按钮、广告标识和结算框架，为直升机、蔬菜、玻璃瓶和小猪制作轻量透明素材。多架直升机与蔬菜使用对象池，场景 UI 序列化到 `AirdropRescueFeedGameScene.scene`，动态部分由脚本驱动。该方案在视频相似度、开发量和资源体积之间取平衡。

## 玩法结构

### 场景层级

- 顶部返回按钮、标题牌、倒计时。
- 标题下方说明牌“空投食物救救小猪”。
- 左侧食物计数，右侧剩余机会。
- 中部天空、云层、直升机生成区、瓶口和瓶身。
- 底部草地与三个广告按钮。
- 全屏结算覆盖层由 `feed_result_layout.mjs` 维护。

### 目标对象

每个目标保存直升机位置、水平速度、吊绳长度、蔬菜位置、状态和生成序号。目标从屏幕外生成，进入可视区域后横向移动，离开另一侧后回收。点击命中区域时从“悬挂”切换到“下落”，保留当时的水平速度并叠加重力。

### 接取判定

瓶口使用独立的窄矩形判定区，瓶身只负责视觉呈现。蔬菜下落穿过瓶口判定区时，按蔬菜中心点和瓶口宽度判断是否成功。成功后停止该蔬菜的下落并播放接取反馈，落地或越过场景底部则扣一次机会并回收。

### 随机节奏

前段保持单架和双架交替，随后提高并行数量、缩短生成间隔和扩大速度差。随机池允许单架、双架、三架以及同屏多颗下落混合出现，避免固定的“两架一组”模式。所有生成点都在屏幕外侧，避免目标凭空出现在屏幕内。

### 失败、复活和广告

失败时显示本局食物数和结算按钮，按现有推荐流规则提供激励视频复活或重新挑战。复活不限次数，每次完整看完激励广告后保留已接到的食物，机会恢复为 5 次并继续当前场面。底部三个广告按钮沿用现有广告标识与广告调用封装，跳关直接完成本关，加时增加 60 秒，提示短暂标出当前最容易接到的蔬菜。广告展示不主动暂停游戏，按钮回调只在广告成功后发放对应效果。
