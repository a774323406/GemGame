## 2026-11-10 推荐流冷启动卡住排查

用户两段录屏：双鸭宿主提示“首帧渲染完成，总耗时4445ms”，之后提示“直玩游戏场景没有加载完成”；抓鸭子则收到“场景加载完成”并展示玩法。录屏无法直接证明 JS 停在哪一行。

本地发现并复现：加载途中收到 feedExit 后，双鸭 start 的 `isReady` 把 exited 当作资源未就绪，唯一一次 7001 上报直接返回 false，后续 feedEnter 也不补报。另一个复现：上报完成后 feedExit，再触摸但宿主没有及时发送 feedEnter，旧触摸条件也拒绝恢复。

修改限于双鸭控制器：稳定渲染就绪只要求场景有效、未销毁、未离开，不以推荐流退出状态阻止上报；真实画布触摸可以从旧退出状态恢复。物理更新与广告仍受进入状态控制，未改共用插屏规则。

新增 `tools/preview_rope_duck_feed.cjs`：仅替换原生 Feed API 边界，运行实际构建的启动加载器、场景、FeedAcquisitionService；旧构建的加载中退出用例等待7001超时，退出后首次触摸用例断言失败；修复后6种双鸭时序及抓鸭子/劈砖对照共8项通过。普通大厅入口、双尺寸触控、暂停/重开、失败/复活与返回回归通过。推荐流路由、规则、难度、场景、控制器与重复插屏20项通过。

项目类型检查使用既有 `--skipLibCheck` 通过；不带该选项时 Cocos SDK 自身声明报 TypedArray、WebGPU 类型及 cc/editor 模块缺失等错误。本次未更改这些声明。Web及抖音构建日志确认成功；构建在用户提出“不需要构建”前完成。用户后续自行构建测试，不再代为构建或上传。
